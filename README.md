# מערכת תמחור, רכש ורווחיות

מערכת Web פנימית לעסק הדפסה וייצור: תמחור, רכש ורווחיות, יחד עם ניהול מידע מוצר (PIM).

מסמך הדרישות המחייב הוא **[`SPEC.md`](./SPEC.md)**. כללי הפיתוח וההכרעות שהתקבלו מול
האפיון מרוכזים ב־**[`CLAUDE.md`](./CLAUDE.md)**.

---

## הרצה

```bash
pnpm install
pnpm db:start                      # Postgres 16 מקומי (Docker אינו זמין בסביבה)
pnpm --filter api db:deploy        # מיגרציות
pnpm --filter api db:seed          # נתוני דמו
pnpm dev                           # api :3000 · web :5173
```

## בדיקות

```bash
pnpm --filter @jaco/core test      # 93 בדיקות, ללא DB וללא שרת
python3 scripts/verify.py          # 40 בדיקות קבלה מול שרת חי (דורש seed נקי)
```

`scripts/verify.py` משנה נתונים בכוונה — הוא מכפיל מחירי ספק כדי לאמת שהצעות מחיר
שמורות אינן זזות. יש להריץ `db:seed` לפניו.

---

## מבנה

```
packages/core/     @jaco/core — מנוע החישוב. טהור: אפס DB, אפס HTTP, אפס React
apps/api/          Fastify + Prisma + PostgreSQL
apps/web/          Vite + React, RTL מלא
scripts/verify.py  בדיקות קבלה מקצה לקצה
```

מנוע החישוב הוא פונקציה טהורה שמקבלת הגדרות, מחירים וקלט ומחזירה תוצאה. ה־API וה־UI
מייבאים את אותה פונקציה, ולכן §58 ("מנוע חישוב אחד; אין לשכפל נוסחאות ב־UI") מתקיים
מבנית ולא רק בהצהרה. כל הכספים ב־`decimal.js` מעל `NUMERIC(18,6)`, בלי עיגול עד התצוגה (§59).

תרומה `19.0825` ב־§61, ושני הספקים ב־§62 מגיעים ל־1,550 ₪. הפערים שלהלן הם התנגשויות

## מה שמור ומה לא

**נאכף:**

- מחיר רכש לעולם אינו נדרס. שינוי סוגר את השורה בתוקף ומוסיף חדשה, כך שניתן לדעת מה
  היה המחיר בכל תאריך (§17).
- הצעת מחיר אימיוטבילית. היא מוגשת מה־Snapshot שלה ולא מחושבת מחדש, ולכן התייקרות
  אצל ספק אינה משנה הצעה שכבר ניתנה (§18, §54).
- `USER` אינו מקבל שדות עלות, אזהרות שנושאות מספרים, או Snapshot. האכיפה בשרת (§57).
- שינוי עלות אינו מעדכן מחירון. המערכת מציגה מחיר נוכחי מול מומלץ (§51).
- אין Hard Coding של 18 / 59% / 45 / 59 / 63 / 227. הם מופיעים ב־seed ובפיקסצ'רים בלבד (§70).

**מודל בלבד, ללא חיבור:**

- §81 — ערוצי מכירה. קיימים המודל, ה־Outbox וממשק ה־Adapter. לא חובר אתר או קופה,
  משום שלא הוגדרו יעדים.

**מחוץ להיקף שלב ראשון (§83):**

Dashboard (§52), ייצוא CSV/Excel/PDF (§56), ייצוא קטלוג ללקוח (§82), מלאי (§66),
הזמנות וחשבוניות (§67).

## הערה עסקית

לפי המחירון של §29 והעלויות שבנתוני הדמו, **הזמנה של 15×21 מתחילה להיות רווחית סביב
4 יחידות**. מתחת לזה ה־setup והכנת הקובץ גדולים מהמחיר.

בנוסף, יחס עבודה של 59% ויעד תרומה של 30% מסתכמים ב־89% מהמחזור, כך שנותרים 11%.
המשמעות היא שהמחיר הדרוש להשגת היעד גבוה בערך פי תשעה מהעלויות הקבועות — ב־15×21 ביחידה
אחת זה 705 ₪ מול 59 ₪ במחירון. זו אריתמטיקה נכונה של הנתונים שהוזנו, לא תקלה, והיא
מצביעה על החלטה עסקית שצריך לקבל: יעד תרומה נמוך יותר לכמויות קטנות, או עבודה לפי שעות
במקום אחוז מהמכירה.
